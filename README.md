### Ответы на вопросы

#### 1. Чем int.TryParse() безопаснее int.Parse()? В каких случаях стоит использовать каждый?
* **Безопасность:** Если пользователь введёт текст (например, `"abc"`), метод `int.Parse()` вызовет исключение (`FormatException`) и программа завершится с ошибкой. Метод `int.TryParse()` в таком случае просто вернёт `false`, не ломая программу, и запишет `0` в `out`-переменную.
* **Применение:** `int.TryParse()` стоит использовать всегда, когда данные поступают из внешних источников или от пользователя (ввод в консоль, веб-форма). `int.Parse()` можно использовать только тогда, когда мы на 100% уверены в корректности строки (например, при чтении системных настроек или жестко заданных строк в коде).

#### 2. Когда switch удобнее, чем цепочка if/else if? Приведите пример из реальной жизни.
* **Удобство:** `switch` удобнее, когда выполняется проверка одного конкретного значения (переменной) на равенство множеству фиксированных вариантов. Он выглядит более структурировано и наглядно.
* **Пример из жизни:** Выбор действия в терминале банкомата или интерактивном меню: 
  * Нажмите 1 — Снять наличные;
  * Нажмите 2 — Проверить баланс;
  * Нажмите 3 — Оплатить связь.

#### 3. Что произойдёт в switch, если убрать break после одного из case?
* В C# компилятор выдаст **ошибку компиляции** (ошибка `CS0163: Control cannot fall through from one case label to another`). В отличие от C++ или Java, в C# запрещено неявное «проваливание» из одного заполненного `case` блока в другой. Исключением являются только пустые `case`, идущие подряд (группировка условий).

#### 4. Чем отличается = от == в С#? Почему это частая ошибка?
* **Отличие:** Оператор `=` — это оператор **присваивания** (записывает значение правого выражения в левую переменную). Оператор `==` — это оператор **сравнения** (проверяет равенство левой и правой части и возвращает `true` или `false`).
* **Почему это ошибка:** Новички часто путают их из-за привычки из школьной математики, где один знак равенства означает совпадение значений. Написание `if (x = 5)` вместо `if (x == 5)` в C# сразу приведет к ошибке компиляции, так как результат присваивания не является логическим типом (`bool`).

#### 5. Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.
* **Можно ли:** Да, вложенные тернарные операторы допускаются синтаксисом.
* **Пример из лабораторной:** 
  `string weather = temp >= 20 ? "тепло" : (temp > 0 ? "прохладно" : "мороз");`
* **Оценка читаемости:** Читаемость такого кода **низкая**. При добавлении даже одного дополнительного уровня вложенности строка становится перегруженной и сложной для быстрого восприятия. В реальной разработке вложенных тернарных операторов советуют избегать, заменяя их на прозрачную конструкцию `if / else if / else`.
